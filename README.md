# OSS Verifier

OSS Verifier is a Theorem program that verifies open-source software. We prove theorems about the compiled fuzz targets of a project. For example, we prove that no input makes a fuzz target crash, hang or fail a sanitizer check. This page tells a maintainer how to enroll a project. A coding agent starts at [AGENTS.md](AGENTS.md).

## Who can enroll

A core maintainer of an open-source project can enroll it. The project needs a public git repository, at least one fuzz target, a security contact, and a language that our builder supports ([docs/project-yaml.md](docs/project-yaml.md#language)). We seeded some projects already, and a maintainer can adopt one ([docs/project-yaml.md](docs/project-yaml.md#seeded-projects)).

## Enroll a project

> **WARNING:** `tools/check` builds the project's `Dockerfile` with network access. Use it only on a project that you trust ([SECURITY.md](SECURITY.md)).

1. Fork this repository.
2. Make `projects/<name>/` from [templates/](templates/): `project.yaml` ([docs/project-yaml.md](docs/project-yaml.md)), a `Dockerfile` and a `build.sh` ([docs/build-contract.md](docs/build-contract.md)).
3. Optional: write a `patch_style.md`. Tell us which findings, reports and patches you want, and how they must look.
4. Run `tools/validate.py projects/<name>`. Correct each problem that it shows.
5. Run `tools/check --twice <name>`. Make sure that it builds each fuzz target, and that the second build has the same bytes.
6. Open a pull request. Complete its checklist.

A coding agent can do steps 2 to 5 with you. Tell it to read [AGENTS.md](AGENTS.md).

## After we merge

1. We build the fuzz targets two times, and pin the SHA-256 of each binary in a lock.
2. We state theorems about these binaries and prove them ([docs/what-gets-proven.md](docs/what-gets-proven.md)).
3. We send each finding privately to `primary_contact`, with a patch when we have one. There is no disclosure deadline, and we do not publish findings.
4. We publish the proofs when the `publish` field tells us to.

Findings and patches are generated by AI models, and they can be wrong or incomplete. We do not promise that a person reviews them before we send them. Review every patch before you use it. We follow your project's policy on AI-generated contributions.

## Pause or leave

To pause the project, set `disabled: true` in `project.yaml`. To leave, remove `projects/<name>/`. Make each change in a pull request.
